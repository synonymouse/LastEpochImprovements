# RepairUnityInterop

Локальный обход ошибки генератора Il2CppInterop для Last Epoch / Unity 6000.4.8f1:

```text
BadImageFormatException: Duplicate type with name '<>O' in assembly 'UnityEngine.CoreModule'
```

Утилита рассчитана на установленный .NET SDK 8 или новее. Она запускается
отдельно от решения мода и не собирает/не заменяет DLL самого мода.

## Что исправляется

В исследованной DLL присутствуют три пустых типа `<>O`, помеченных как
вложенные, но не имеющих родителя. Они получают корректную видимость
`NotPublic` и разные полные имена:

- `<>O`
- `UnityEngine.<>O`
- `UnityEngine.Rendering.<>O`

Все три типа сохраняются. Используются уже существующие строки пространств
имён в metadata heap; правятся только поля `Flags` и `Namespace` трёх строк
таблицы `TypeDef`. В проверенной DLL это изменение девяти байт.
Номера строк и metadata tokens, IL, RVA, MVID, размер DLL и остальные байты
сохраняются. Утилита проверяет ожидаемую структуру типов и допустимые изменения
перед записью. Другие варианты дубликатов она не исправляет.

## Применение

Закрыть Last Epoch. Из корня репозитория выполнить:

```bat
dotnet run --project tools/RepairUnityInterop/RepairUnityInterop.csproj -- "C:\Program Files (x86)\Steam\steamapps\common\Last Epoch\MelonLoader\Il2CppAssemblies\UnityEngine.CoreModule.dll" --apply
```

Сначала создаётся исправленный файл, затем он заменяет оригинал через
`File.Replace`. Оригинал сохраняется рядом под именем:

```text
UnityEngine.CoreModule.dll.interop-repair-<дата-время>.bak
```

Если дубликатов нет, повторный запуск ничего не меняет. Для подготовки копии
без установки вместо `--apply` указать путь к отдельному выходному файлу.
Утилита отказывается перезаписывать уже существующий выходной файл.

При `--apply` используется уникальный staging-файл с GUID; после неудачной
замены он удаляется. Оставшийся файл от старой прерванной попытки не блокирует
следующий запуск автоматического ремонта.

После применения запустить игру обычным способом. Не использовать
`--melonloader.agfregenerate` для этого запуска: новая генерация может
восстановить дефектную DLL. В `UserData/Loader.cfg` параметр
`force_regeneration` должен быть `false`.

По новому `MelonLoader/Latest.log` проверить загрузку IL2CPP support module
и инициализацию мода. Исправление загрузки этой DLL не является подтверждением
совместимости всех игровых патчей после обновления.

## Откат и повторная генерация

Для автоматического применения после регенерации доступен плагин
[AutoRepairUnityInterop](../AutoRepairUnityInterop/README.md), использующий
тот же код проверки и исправления метаданных до загрузки модов.

Для отката с закрытой игрой заменить `UnityEngine.CoreModule.dll` сохранённой
резервной копией, вернув ей исходное имя.

Это обход для уже сгенерированного файла, а не исправление самого генератора.
После обновления игры или пересоздания interop-сборок сначала проверить новый
лог; при повторении того же дефекта утилиту можно применить заново.
